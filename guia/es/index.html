La regla del sí

La regla del sí

“Regla del sí” es el nombre que el kit le da a la forma de aprobación de Nod; no es un botón del producto. El sí es la solicitud que hiciste, una regla o rutina que guardaste, o el botón para aprobar; lo que no pediste espera tu sí; cada pago solicita el código de seguridad de la tarjeta en cada compra. La revisión puede equivocarse.

1. Regla en el servidor

La revisión de permisos se ejecuta fuera de la solicitud al asistente. Compara la acción exacta con tus palabras y reglas, usando el criterio de otro modelo.

2. Lo que lee son datos

Los correos electrónicos, las páginas y los resultados de las herramientas no son órdenes ni conceden permiso.

3. “Vault”: almacén privado

Las contraseñas y los datos de tarjetas se introducen en un formulario privado. El modelo no recibe los secretos; el servidor puede leerlos durante el uso y el sitio recibe lo que se envíe.

4. Código en cada compra

Cada pago requiere su propia aprobación y un código de seguridad. El código nunca se guarda ni se envía al modelo ni al historial. Guardar una tarjeta no autoriza compras.

Las lecturas y los borradores normalmente se ejecutan. Para exigir una revisión, usa la regla “preguntar antes” (“ask first”). Aprobar una acción no autoriza todas las siguientes.

El límite mensual en “Usage” es otra protección: solo se aplica al costo del modelo por API con precio conocido, no a las compras con tarjeta. La cuota de ChatGPT y el uso local sin precio no se incluyen en ese límite.

Los 7 principios de confianza

  1. La autoridad viene solo de ti. El contenido leído no otorga permiso.
  2. El modelo no ve tus secretos. El servidor completa los campos privados y oculta los valores.
  3. Acciones exactas, ejecutadas una vez. Cambiar el objetivo o los argumentos requiere una nueva autorización; un resultado incierto no autoriza a repetir la acción.
  4. Puedes revisarlo. “Usage” registra usos, costos y acciones.
  5. Tu computadora, tu modelo. Tú eliges dónde se ejecuta y qué proveedor usar.
  6. Código abierto. Los datos de uso se pueden desactivar; los registros de conversación solo se envían cuando están activados.
  7. Transparencia sobre los límites. La revisión puede fallar y, al usarlos, los secretos pasan por el servidor y el sitio.

Entiende los términos

Cuando quieras ir más allá de la app

n8n es una empresa alemana conocida por la herramienta de automatización n8n, que conecta apps sin programar; Nod es una app aparte, hecha por el mismo equipo, y no necesita n8n para funcionar.

Una VPS (servidor virtual alquilado) puede mantener Nod encendido. Docker (herramienta que ejecuta programas en entornos aislados) se usa en la opción de servidor; el acceso puede usar un token de acceso (contraseña del servidor) y un túnel SSH (conexión protegida entre tu computadora y el servidor). MCP (estándar de conexión entre asistentes y herramientas) permite integrar aplicaciones como n8n. No hace falta configurar un servidor para empezar con la aplicación de escritorio.

25 consejos para empezar

25 consejos para empezar

Sugerencias editoriales, no relatos de uso. Abre cada bloque para leerlo. La base documental está en FATOS.md (en portugués).

Antes de instalar · 3 consejos
  1. Elige dónde se almacenan los datos.

    Elige escritorio para usarlo en tu computadora o servidor para acceder desde otros dispositivos. La documentación indica que conectar la aplicación de escritorio al servidor no migra tus datos locales.

  2. Verifica tu sistema.

    Revisa los requisitos antes de descargar. En la computadora de escritorio, no necesitas instalar Docker; para usar Windows localmente se requiere WSL 2 (función que ejecuta Linux dentro de Windows) y para Linux local se requieren virtualización y una bóveda de secretos del sistema.

  3. Empieza como investigación.

    Considera la vista previa de investigación (versión experimental, aún en evaluación) como algo que debes seguir de cerca. Nuestra sugerencia es empezar con lecturas y borradores, porque la documentación indica que la revisión de permisos puede equivocarse.

Elegir el modelo · 3 consejos
  1. Verifica la conexión, no solo el nombre.

    Consulta la lista en “Settings → Models”. Que un modelo aparezca en el catálogo no demuestra que tu cuenta pueda usarlo. Si eliges ChatGPT, la documentación exige Plus o Pro.

  2. Elige teniendo en cuenta la seguridad.

    La documentación informa que GPT-6.1 Sol y Claude Opus 5.5 acertaron en las 240 decisiones. Claude Haiku 5.5 dejó pasar 8 acciones inseguras en esta prueba; no generalices el resultado.

  3. En el entorno local se necesitan acciones y contexto.

    Para Ollama u otro servicio compatible con OpenAI, revisa las acciones y asegúrate de contar con al menos 64.000 tokens (fragmentos de texto que se usan para medir el uso y el costo del modelo) de contexto. Revisa también qué conexión realiza la revisión de permisos: podría enviar datos a otro servicio.

Conecta las apps sin abrir demasiado el acceso · 3 consejos
  1. Conecta solo lo necesario.

    Nuestra sugerencia es activar solo la aplicación que necesites para la primera tarea. Puedes omitir las conexiones durante la configuración inicial. Lee el consentimiento: un permiso puede abarcar toda tu bandeja de entrada.

  2. Verifica qué cuenta está activa.

    En “Apps”, revisa las identidades y los permisos antes de solicitar cualquier acción. Usa el botón “+” o “Add account” cuando esté disponible; Notion, Linear (aplicación para organizar tareas y proyectos) y n8n usan sus propios MCP.

  3. Trampa: no todo se queda localmente.

    No interpretes “se ejecuta en tu computadora” como “nada se envía a la nube”. La doc indica que, por defecto, las solicitudes de las aplicaciones pasan por n8n y Composio. ZDR tiene un alcance limitado y no reduce los permisos. Confidencialidad/LGPD: por defecto, los datos de clientes que se leen en las aplicaciones pasan por el servicio de conexión n8n/Composio y llegan al proveedor del modelo. Empieza con datos propios o anonimizados.

Seguridad y privacidad · 6 consejos
  1. Desactiva “Share usage data”.

    Abre “Settings → Privacy & data” y desactiva “Share usage data” si no quieres que se envíen más datos. Está activado para los usuarios nuevos; desactivarlo no borra lo que ya se envió.

  2. Al principio, mantén desactivados los registros de conversación.

    Nuestra sugerencia es mantener “Share conversation traces” desactivado mientras evalúas el producto. Es un control independiente y ya viene desactivado. La eliminación de datos personales puede dejar pasar algunos detalles.

  3. Define tu límite mensual.

    Con un modelo por API seleccionado, abre “Usage” y ajusta el límite a lo que estás dispuesto a gastar. La doc indica US$ 200 en la configuración inicial actual; es posible que las instalaciones anteriores no tengan límite. El plan y el uso sin precio tienen reglas distintas.

  4. Usa el formulario de “Vault”.

    Escribe las contraseñas y los códigos en los campos privados, no en la conversación. Verifica la cuenta y el sitio. Para pagar, apruebas cada pago e ingresas el código de seguridad, que nunca se guarda.

  5. No conectes todo el primer día.

    Nuestra sugerencia: deja para después las tarjetas, las cuentas adicionales, “Include sensitive details” y los permisos para actuar por su cuenta. Empieza con borradores; revisa la preparación automática en “Settings → Notifications”, ya que las páginas no coinciden sobre la configuración predeterminada.

  6. Trampa: la IA participa en la decisión.

    La revisión de permisos se ejecuta en el servidor, pero tu criterio también depende de un modelo. No confundas el control de acciones fuera de lo solicitado con una decisión infalible. Pide aprobación antes de las acciones que quieras revisar.

Dejarlo activo 24/7 · 4 consejos
  1. Dimensiona la VPS.

    Empieza por la referencia de la doc: Linux AMD64/ARM64 (tipos de procesador; elige el paquete correspondiente a tu equipo), 2 núcleos, 8 GB y 50 GB. Usa el checklist del servidor; las tareas simultáneas y los modelos locales pueden requerir más capacidad.

  2. Mantén el Mac mini encendido.

    Reserva memoria para Docker y para macOS. Activa el inicio de Docker Desktop (aplicación que ejecuta entornos aislados en la computadora) después de iniciar sesión. Después de reiniciar o de un corte de energía, inicia sesión en la cuenta y verifica que Nod haya vuelto.

  3. Usa un túnel y protege el token de acceso.

    Para el acceso privado, sigue las instrucciones del túnel SSH del checklist y mantén la conexión abierta. El token de acceso da acceso completo al asistente; no lo trates como un enlace de solo lectura. Un dominio público requiere HTTPS (conexión web cifrada).

  4. Guarda una copia de seguridad que se pueda recuperar.

    Antes de actualizar, usa el procedimiento de copia de seguridad de la doc. Guárdala fuera del servidor, cifrada y con acceso restringido. Incluye la clave de la bóveda y la revisión correspondiente; copiar solo la base de datos no recupera las credenciales.

Primeras tareas que valen la pena · 2 consejos
  1. Empieza con un resumen privado.

    Usa la solicitud de rutina de correo electrónico o resumen de reunión en TAREFAS.md. Nuestra sugerencia es revisar el texto antes de permitir los envíos. La documentación presenta estas tareas como ejemplos.

  2. Haz una supervisión sencilla.

    Pide programar una tarea de precios y prohíbe las compras en el mismo pedido. Verifica la zona horaria y la próxima ejecución. En “Scheduled”, usa “Run now” y lee el resultado; la máquina debe permanecer encendida.

Memoria · 2 consejos
  1. Revisa lo que aprendió.

    Abre “Settings → Memory” para ver la fuente, editar o eliminar notas. Las notas personales se basan en lo que proporcionas; el estilo de los correos que envías se aprende por separado.

  2. Entiende “Let go” y “Skills”.

    “Let go” archiva las notas reemplazadas o vencidas; puedes restaurarlas u olvidarlas. Hay mantenimiento cada hora. Revisa las “Skills” aprendidas: pueden contener errores y nunca dan permiso para actuar.

Dónde todavía falla · 2 consejos
  1. Trampa: una prueba de evaluación no es una garantía.

    El 98% y las cero acciones inseguras corresponden a cuentas y sitios simulados con GPT-6.1 Sol. Son 226 tareas repetidas 3 veces. Que no haya inyecciones de memoria tampoco significa que el correo no tenga ninguna influencia.

  2. Verifica antes de repetir.

    Si un pago termina como “resultado desconocido” (“Result unknown”), verifica el pedido antes de volver a intentarlo. Las tareas programadas se detienen cuando se apaga la máquina. La conexión de WhatsApp por QR usa Baileys, un cliente no oficial: existe el riesgo de que restrinjan la cuenta y una actualización de WhatsApp puede interrumpir la conexión. Nuestra sugerencia: si usas WhatsApp con clientes, prefiere Telegram para conversar con Nod. No dependas de un futuro alojamiento administrado.

Guía de uso

¿Vas a usarlo en una computadora con ChatGPT Plus? Sigue solo estos pasos

La aplicación no requiere herramientas de desarrollo. Para esta primera prueba, usa una cuenta de correo propia.

1

Descarga la aplicación Nod

En macOS 14 o posterior, consulta el tipo de procesador en “Acerca de esta Mac” y descarga para Mac Apple silicon o Mac Intel. En Windows 11 x64, descarga el instalador de Windows, todavía en vista previa. La aplicación y el entorno local ocupan cerca de 1,8 GB en Mac y 2,1 GB en Windows. Linux x64 usa Flatpak (formato de instalación de aplicaciones de Linux), en vista previa: descarga todas las partes y verifica el checksum (código que verifica la integridad de la descarga), siguiendo el lista de verificación de escritorio (en portugués).

2

Instala, abre y elige “Get started”

En Mac, abre el DMG, arrastra Nod a “Applications” y abre la aplicación; confirma “Open”. En Windows, ejecuta el instalador, verifica que el editor sea “n8n GmbH” y abre Nod desde el menú Inicio. Elige “Get started” para usarlo en esta computadora. Si usas Windows localmente, sigue los pasos de preparación de WSL 2, con virtualización y 20 GB libres; reinicia si se solicita y vuelve a abrir Nod. Mantén la conexión a internet mientras prepara el entorno. Windows puede mostrar un aviso de SmartScreen porque la app es nueva, y Nod pide autorización de administrador para preparar WSL; si la virtualización está apagada, se activa en la BIOS de la computadora (pide ayuda a quien sepa, si nunca lo hiciste).

3

Inicia sesión con ChatGPT

En la configuración inicial, omite el correo electrónico con “Continue without email” y las preguntas personales con “Not now”. Al elegir el modelo, selecciona “OpenAI” y “Sign in with ChatGPT”; inicia sesión en tu cuenta Plus o Pro. El uso consume la cuota del plan. Revisa la opción para compartir registros de conversación y omite el correo de novedades si lo prefieres. En “Settings → Privacy & data”, también puedes desactivar “Share usage data”, que está activado para los usuarios nuevos.

4

Conecta solo Gmail

Abre “Apps → Connect”, elige Gmail, inicia sesión y revisa los permisos que solicita Composio. Un permiso puede abarcar toda la bandeja de entrada. Conecta solo tu propia cuenta, la que usarás para la prueba; deja las demás aplicaciones para después.

5

Solicita la tarea 1 y revisa los borradores

Copia la tarea 1 — Rutina de correo electrónico, reemplaza [cuenta] por tu Gmail y envíalo en la conversación. La solicitud limita el trabajo a resúmenes y borradores. Lee el resultado entregado y revisa las acciones en “Usage”; una confirmación de recepción no demuestra que la tarea haya terminado.

Para quienes usarán un servidor

Los siguientes pasos son para mantener tu propio servidor. Un servidor pertenece a una persona; el token de acceso es la contraseña que da acceso completo al asistente.

1

Descarga el kit y lee el checklist

Puedes descargar el ZIP y descomprimir. Si prefieres clonar, instala Git y abre una terminal (ventana para escribir comandos). Estos comandos descargan el kit; no instalan Nod.

git clone https://github.com/inematds/nod-n8n.git
cd nod-n8n
2

Revisa el equipo del servidor

Referencia: Linux AMD64/ARM64, 2 núcleos, 8 GB de memoria y 50 GB de disco, o Mac con Docker Desktop. Necesitas Docker 25+, Compose v2 (herramienta que inicia los servicios Docker en conjunto), OpenSSL (herramienta criptográfica usada en la configuración) y verificación de integridad. Ejecuta el verificador en la máquina elegida. Solo lee datos locales; no instala ni ejecuta Docker. Salida: LISTO o FALTA(N) elemento(s). Que aparezca PRONTO no demuestra que Nod o Docker funcionen.

bash ferramentas/checar_servidor.sh
3

Instala y protege el servidor

Sigue el lista de verificación del servidor (en portugués): la documentación todavía describe paquetes privados, así que no des por sentado que tienes acceso. El checklist también incluye la alternativa de compilar el código oficial. Después, sigue el lista de verificación de seguridad del primer día (en portugués). En la aplicación, “Connect to a server” solicita la dirección y el token de acceso; esto no migra tus datos locales. Si usas un modelo por API, ajusta el límite de costo en “Usage”.

Dónde todavía falla

Dónde todavía falla

Computadora apagada = detenida

Para el uso local, Nod debe estar abierto y la computadora debe permanecer encendida y conectada. Un servidor activo sigue funcionando después de cerrar el cliente. El alojamiento administrado está previsto para el futuro.

WhatsApp por QR puede desconectarse

La conexión de WhatsApp mediante QR usa Baileys, un cliente no oficial: existe el riesgo de que restrinjan la cuenta y una actualización de WhatsApp puede interrumpir la conexión. Nuestra sugerencia: si usas WhatsApp con clientes, prefiere Telegram para conversar con Nod.

Todavía está en vista previa

Es una versión de investigación. La revisión de permisos usa un modelo y puede equivocarse; los sitios y las integraciones también cambian.

Este kit organiza la documentación; no es un relato de instalación o uso. Consulta la base documental (en portugués), o Nod, a documentación oficial e o código oficial.
